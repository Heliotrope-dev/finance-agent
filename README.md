# Invest Agent

多市场（A股 / 港股 / 美股）行情查询 + 财务数据 + 新闻资讯交叉验证工具，同时也是我自己在用的一套个人投资 AI 助理——代码全部开源，我平时怎么用 AI 辅助看盘、这套判断逻辑历史上准不准，都摆在这里给你参考，不是包装成面向公众的投顾服务。详情页等大部分模块 AI 只做交叉核实和总结，不做黑箱荐股；首页的"AI 投研候选"模块是唯一的例外，会明确给买入/卖出/持有/观望结论——这是我自己每天在看的东西，公开出来是为了透明（连历史判断准不准都摆出来，不是只报喜不报忧），不构成对任何人的投资建议，请自行判断。

线上地址：[invest.heliotrope.online](https://invest.heliotrope.online)

## 设计原则

- **只摆事实，先讲依据**：详情页先看一手资讯（官方公告/富途资讯/财新摘要，各市场优先级不同）和原始数据（K线、财务表、统计指标），AI 分析摆在后面，交叉核实新闻、财务、技术面是否一致，不直接给"买入/卖出"这类指令。
- **技术面信号本地算，不靠 AI 编**：均线金叉死叉、MACD、盘中实时动量这些都是 pandas 本地算好喂给 AI 的，AI 只负责核对是否跟消息面一致，避免"技术面尚可"这种空话。
- **诚实的追踪记录**：每次生成交叉验证分析会记录当时价格和 AI 判断的方向倾向，满 7 天自动补录价格算一个方向一致率（按总体/按市场/按方向分别拆开统计）——这是历史记录的客观统计，不是"AI 荐股胜率"，页面上会明确标注不构成投资建议。
- **"AI 投研候选"是刻意分开的例外，但不是不负责任的例外**：首页这一个模块反过来明确给买入/卖出/持有/观望结论——判断维度也更完整：基本面（盈利/成长/负债/估值）为主，技术面辅助确认，额外加了"52 周价格位置"（现价离高点/低点多远）防止"基本面好就无脑追高"或者"基本面差就不敢碰已经跌透的股票"这类常见误区。全市场候选池是用 Futu 官方筛选接口按市值/估值/盈利增速做的量化初筛（不是本地维护的知名股名单），跟"只摆事实"那批模块共用同一套真实数据源，只是让 AI 多做一步"综合给结论"。不是每次访问现场跑——AI 判断成本不低（实测一次全市场扫描约 40 次调用），改成私有脚本每个工作日收盘后跑一次、结果落库，首页只读最近一次结果，同时也会通过微信私发给我自己。**同样有"记录判断→事后回填价格→算方向一致率"这套追踪机制，而且这个历史一致率直接显示在首页**（不是只在代码里算了没人看得到）——判断准不准，是可以被访客当场核实的，不是自卖自夸。样本量还小的阶段，页面会如实说明"还没有足够历史数据"，不会为了显得有说服力就提前拿小样本吹结论。

## 功能

- **AI 投研候选**（首页）：全市场港美股量化初筛 + AI 综合基本面/技术面/52周价格位置给买入/卖出/持有/观望结论，每个工作日收盘后由私有脚本 `advisor.py` 更新一次，首页展示最近一次结果（不现场重新跑）。
- **多市场行情**：A 股按涨跌幅展示，港股按东财人气榜排热度，美股用固定核心股名单，都支持点击卡片直接跳转详情页；"行情"页拆成多个独立 `@st.fragment`，点某一块的交互按钮不会带动其它模块一起重新拉数据。
- **实时价格**：详情页 + 持仓列表价格每 3 秒自动刷新（`st.fragment(run_every=3)`），有真实数据变化时会有红涨绿跌的闪烁提示，不是整页定时重刷。
- **分时图**：A 股用新浪分钟数据，港股/美股优先走本地 Futu OpenD 网关的真实分时推送，没有 Futu 连接时退化成日 K。
- **AI 深度分析**：资讯解读、财务摘要、对比大盘、技术面与消息面交叉验证、总结性分析（带 0-100 综合评分），打开详情页自动生成，流式（打字机效果）显示，生成后缓存，不会重复调用。
- **指数详情页**：K 线/分时图 + 成分股 + AI 分析。宽基指数（上证/深证/创业板/恒生/国企/标普/纳指/道琼斯）用"这个市场当前涨幅最大的股票"做代理指标；"恒生科技"这类行业主题指数改用手动维护的真实成分股名单 + Futu 批量快照，不再混入不相关行业的公司。
- **热门板块**：行情页每个市场下方展示成交额最高的 9 个行业板块（红涨绿跌），"更多板块"展开到前 30；A 股走同花顺行业板块接口，港股/美股走 Futu 板块快照，用成交额代理热度，不是官方板块人气榜。
- **持仓分析**：搜索添加时自动判断股票在哪个市场（"苹果"只在美股上市就直接添加，"阿里巴巴"港股美股都有就弹出来问），填股数/金额记为真实持仓（不填只是关注），持仓占比环形图（多币种统一折算人民币）、今日收益实时刷新、卖出按比例扣减成本，跨市场统一管理，多只股票的行情并发拉取（不用一只一只顺序等）。
- **移动端适配**：核心的卡片/表格类布局在窄屏下会换行展示，不是只在桌面宽屏下能用。
- **登录/账号**：邮箱+密码登录，跟 math-agent 共用同一套 Supabase 账号体系，登录 token 只存 `session_state`/`localStorage`，不写进 URL query params（避免明文留在浏览器历史和 Nginx access log 里）。

## 项目结构

```
app.py              # 入口：登录/鉴权、行情+持仓分析+详情页的全部UI渲染
data_sources.py      # 所有外部数据源：AkShare/BaoStock/新浪/东财/财新/Futu OpenAPI
analysis.py          # DeepSeek流式分析（资讯/财务/大盘对比/技术面消息面交叉验证/总结）
charts.py            # K线/均线/MACD/成交量图表 + 本地统计指标计算（不经过AI）
tracker.py           # SQLite：分析记录+方向一致率、持仓(positions表)、搜索历史、投研候选(advice表)
advisor.py           # 私有脚本：全市场港美股量化筛选+AI综合判断，不进Streamlit运行时，
                     #   由OpenClaw cron每工作日收盘后跑一次，写进advice表+微信私发站长
auth.py              # 登录鉴权（从math-agent移植，共用同一套Supabase账号体系）
theme.py             # 涨跌红绿色常量，app.py/charts.py统一从这里引用
data/
  track_record.db    # 追踪记录/持仓/搜索历史，不入库
```

## 技术栈

- 数据源：[AkShare](https://akshare.akfamily.xyz)（免费开源）+ [BaoStock](http://baostock.com)（A 股主数据源，稳定免注册）+ 新浪财经（实时行情/分时）+ 东方财富公告中心（A 股官方公告，永久免费）+ 财新（资讯兜底）+ [Futu OpenAPI](https://openapi.futunn.com)（港股/美股实时行情、分时、资讯搜索，需要本地/服务器跑 OpenD 网关）
- 分析：DeepSeek（`deepseek-v4-flash`），流式输出
- 前端：Streamlit（`@st.fragment` 拆分自动刷新粒度，并发线程池加速持仓取数）
- 账号：Supabase
- 追踪记录：SQLite（`data/track_record.db`，不入库）
- 部署：VPS + Nginx + systemd，GitHub Actions 在 push 到 main 后自动部署

## 本地运行

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
# 在 .streamlit/secrets.toml 填入 DEEPSEEK_API_KEY / SUPABASE_URL / SUPABASE_KEY
streamlit run app.py
```

港股/美股的实时行情、分时图、资讯搜索需要本机或服务器另外跑一个 [Futu OpenD](https://openapi.futunn.com/futu-api-doc/quick/opend-forward.html) 网关（监听 `127.0.0.1:11111`），没有这个连接时会自动退化成延迟行情/日 K/财新新闻兜底，不影响基本可用性。

## 已知限制

- 东方财富接口对高频请求有临时限流，`data_sources.py` 里对东财相关调用加了请求间隔和重试（`_with_retry(..., throttle=True)`），其它数据源（新浪/BaoStock/财新）不受这个限流影响。
- akshare 内部部分接口用 py_mini_racer（V8 引擎）做反爬 JS 执行，不是线程安全的，全局加了 `_akshare_js_lock` 串行化；BaoStock 的 login/logout 是全局会话状态，同样加了 `_baostock_lock`。
- 指数"成分股"板块：宽基指数用"这个市场当前涨幅最大的一批股票"代理，不是严格的官方成分股名单；"恒生科技"这类行业主题指数改用手动维护的真实名单（`data_sources.py` 里的 `_HSTECH_CONSTITUENTS`），按季度调整，可能跟最新官方名单有出入，页面上会标注生效日期。
- 港股/美股实时行情、分时图、热门板块等依赖本地 Futu OpenD 网关。所有 Futu 查询统一走一个进程内常驻的专属 worker 线程（`_futu_call`）——连接和每一次方法调用必须发生在同一个线程，否则 Futu SDK 内部状态会错乱直接卡死不返回（不是慢，是彻底没有响应），这是过去排查一次"恒生科技成分股一直加载不出来"才定位到的坑，现在所有 Futu 调用点都统一走这一条路径。进程刚起来时第一次建立连接实测要几十秒到几分钟不等（Futu 自己的登录握手延迟），这段时间内相关功能会先降级显示"暂不可用"，连接成功后自动恢复。
- 只支持股票和指数，不支持基金/债券/期货/期权。

## 踩过的坑

**Futu 连接和调用不在同一线程，会直接卡死不返回**

早期的 `_get_futu_ctx()` 设计是"用一个后台子线程建立连接，把连接对象传回调用方线程直接用"——这正是 Futu SDK 会导致内部状态错乱的反模式，只是没被系统性发现过。排查"恒生科技成分股一直转圈加载不出来"时才第一次复现：直接在同一线程里连接+查询，0.1 秒返回；换成"连接在子线程、查询在主线程"，同样的请求能卡住 90 秒以上没有任何响应。检查其余功能点后发现持仓实时价、热门板块、全市场搜索、K 线、分时订阅等十几处调用全部踩了同一个坑，只是这些路径平时凑巧没被同时压测到。

修复：改成一个进程只用一个常驻 worker 线程持有 Futu 连接，所有查询请求排队交给这一个线程处理（`_futu_call`），从架构上保证连接和调用永远同一线程，不再靠"记得不要跨线程调用"这种约定去维持正确性。

**AI 分析概率性返回空内容**

`deepseek-v4-flash` 会输出一段隐藏的思考过程（`delta.reasoning_content`，跟正式回答的 `delta.content` 是两个字段），但这段思考内容跟正式回答共用同一个 `max_tokens` 预算。某些分析函数的 `max_tokens` 设得偏小（比如指数分析原来是 400），运气不好模型的思考过程就把预算全部吃完，正式回答一个字都不剩——用户看到的是"分析失败：AI 没有返回任何内容"，看起来像接口调用失败，实际上请求本身是成功的，只是内容被思考过程占满了。逐一排查所有调用点统一调大预算解决，中途还漏掉过两处：先是指数分析（400→够用），后是 `summarize_overall` 总结性分析（1200→3000）；这次是 `cross_validate` 交叉验证（2000→4000）——它是所有模块里唯一要求四段完整结构化输出的调用点，正文本身就比其它模块长，之前却一直留在跟短总结类函数一样的默认值上，没被前几轮排查覆盖到。

**A股指数"成分股"混入了不属于该板块的股票**

"涨停股池"这类结果覆盖全市场，直接拿来当某个宽基指数（比如创业板指）的成分股展示时，没有按交易所/板块前缀过滤，会混进 60/68 开头（上交所主板/科创板）的股票——这些公司压根没在创业板上市。加了 `_A_INDEX_CODE_PREFIX` 按代码前缀过滤后修复。

**登录 token 写进 URL 触发无限刷新循环**

为了"token 不该明文留在地址栏"这个安全考虑，登录成功后加了一行 `del st.query_params["_auth"]` 把token从URL里删掉——结果这行代码本身触发了 Streamlit 的自动 rerun（`st.query_params` 的任何修改都会触发重跑），跟页面里"用 localStorage 自动登录"的 JS 桥接逻辑产生竞态，页面陷入每 5-6 秒刷新一次的循环。通过 nginx access log 里同一个 token 反复出现的 `GET /?_auth=...` 请求定位到问题，最终去掉这一行、保留"token 从一开始就不写进 URL"这个更早的修复即可，两个安全考虑没法同时用这种方式做，选了风险更低的那个。

**内部切换（非整页导航）时上一页内容残留**

行情/持仓这类靠 `st.radio` 触发的内部 rerun 切换页面时，切换前的卡片内容会残留一部分，跟切换后的新内容叠在一起。原因是加载遮罩用 `st.components.v1.html()` 注入 JS，如果两次 rerun 之间传入的内容字节完全相同，Streamlit 前端判定"没有变化"，不会重新挂载这个 iframe，脚本也就不会重新执行——遮罩只在真实的整页导航（点 `<a href>` 链接、浏览器重新加载文档）时才生效，纯靠 Streamlit 内部状态触发的 rerun 完全绕过了这层去重之外的场景。修复：给注入内容嵌一个每次 rerun 都变化的时间戳注释，让内容字节永远不同，保证每次 rerun 都强制重新挂载。

**详情页 URL 参数没转义，反射型 XSS 叠加 token 写回 URL，能被拿去接管账号**

详情页顶部那行股票/指数名称是直接从 URL 参数（`open_name`/`open_symbol`/`open_index_name`）里取出来渲染的，没走项目自己写好的 `_esc()` 转义就塞进了 `unsafe_allow_html=True`——同一份代码里 `_render_sector_detail` 其实是转义过的，这里纯粹是漏掉了。更麻烦的是它跟另一个问题凑在一起：前面记录过"token 写进 URL 会触发无限刷新循环"，当时的解法是干脆不删 URL 里的 token；但 `_auth_qs()` 又把这个 token 拼进了几乎所有卡片跳转链接，结果正常点几下鼠标，7 天有效的登录 token 就会明文出现在地址栏、浏览器历史、Nginx 日志里——绕了一圈又把当初想避免的事重新引进来了。这两条是交给 Fable 5 做独立审查时挖出来的，跟 math-agent 那边的做法一样。

修好了：URL 参数补上 `_esc()`；token 那边改成登录校验通过后用浏览器端 `history.replaceState` 把地址栏里的 `_auth` 摘掉（不动 `st.query_params`，不会触发 rerun，也就不会重现之前的刷新循环）。**留了一个没解决的尾巴**：链接被点开那一次请求本身还是会把 token 带到服务端，Nginx 日志里照样会留一条明文，真要彻底解决得在 Nginx 那层做日志脱敏，目前只是把"常驻浏览器历史"这半个问题堵上了。

**三处数据源没做异常保护，接口一抖就整页崩掉——包括详情页默认打开就看到的那个视图**

`get_financial_abstract`、`get_benchmark_history` 的港股/美股分支、A 股分时图底层的 `_sina_minute_intraday`，这三处都是裸调用，没有 `_with_retry` 也没有 try/except。最后一个尤其麻烦：A 股详情页默认打开的就是"分时K（今日）"这个 tab，新浪接口稍微抖一下，整个详情页直接崩掉，不是页面上别处那种"暂不可用"的优雅降级——跟前面几条踩坑记录里反复强调的原则正好相反，只是一直没被排查到。三处都补上了兜底，取数失败统一返回空结果，复用调用方原本就有的降级展示。

**Futu worker 线程没有内部超时，真卡死会让整个 Futu 功能永久失效**

`_futu_call` 统一走一个常驻 worker 线程，之前只在调用方那边设了等待超时——worker 线程本身如果真卡死（不是慢，是彻底不返回，前面也描述过这类症状），调用方超时只是提前拿到降级结果，worker 还是卡在原地出不来，后面所有请求都排不进去，也没有任何自愈手段，只能重启进程。加了一个看门狗线程盯心跳，超过 180 秒判定卡死就换一代新 worker 顶上，涉及共享状态的地方都加了 epoch 校验防止新旧 worker 互相打架。**这条改动没有真实 Futu OpenD 环境验证过**，上线后得盯着健康面板确认没误伤正常请求、真卡死的时候确实能自愈。

**加 GitHub Actions 自动部署时，顺带发现 math-agent 那边的部署密钥已经失效一个多月了**

之前 finance-agent 一直是手动 SSH 上服务器拉代码重启服务，这次照着 math-agent 的方式配了一份一样的 workflow。配置过程中才发现 math-agent 自己的自动部署早就悄悄坏了——8/13-14 服务器迁移到新机器后，GitHub 仓库里保存的部署密钥没跟着更新，一直静默失败到现在都没人发现（部署失败没有任何提醒）。两边仓库的密钥都已经改成指向新服务器了。**教训：部署密钥这类基础设施配置跟应用代码是两条线，迁移服务器时很容易只顾着搬代码搬服务，忘了这些平时不会主动报错的东西也得跟着改。**
